# 진(DJINN)-lite — 토끼풀용 공공데이터 취재 알림 봇

노르웨이 트롬쇠 지역신문 이트롬쇠가 만든 AI 취재지원 시스템 '진(DJINN)'을 참고해,
학생 언론 토끼풀 규모에 맞게 축소한 버전입니다. 원본은 노르웨이어로 훈련한 중앙
모델과 뉴스룸별 지역 모델을 따로 두지만, 이 축소판은 모델을 훈련하지 않고 범용 LLM
한 번 호출로 같은 역할을 대신합니다. 원본과 마찬가지로 **AI는 기사를 쓰지 않습니다.**
취재 단서를 찾아 우선순위를 매길 뿐이고, 취재와 검증, 기사 작성은 학생 기자가 합니다.

판단 기준은 상상으로 만든 것이 아니라 **편집장이 직접 판정한 268건**에서 뽑았습니다.
다섯 차례에 걸쳐 카드로 만들어 기사감 여부를 받고, AI 판단과 갈린 42건을 되짚어
기준을 고치고, 다음 회차에 그 수정이 작동하는지 시험하는 과정을 반복했습니다.
그 이력과 근거는 기준 문서에 정리되어 있습니다.

가장 중요한 결론 하나는 **토끼풀이 학생 정책 전문지가 아니라 청소년의 눈으로 보는
종합지**라는 것입니다. 12·3 내란 때 호외를 낸 신문이고, 정치·과학·기후·재난도
또래가 알아야 할 일이면 다룹니다. 그래서 판단의 물음은 "이 문서가 학생에게 규칙으로
적용되는가"가 아니라 **"또래가 이 소식을 알아야 하는가"** 입니다.

지금 단계는 여전히 기준을 검증하는 중이라 우선순위와 상관없이 전부 슬랙에 올립니다
(`config.MIN_PRIORITY_TO_POST = "하"`).

## ⚠️ 지금 바로 확인할 것: 워크플로 파일 중복

저장소에 `.github/workflows/djinn-lite.yml`과 `.github/workflows/main.yml`
두 파일이 같은 내용(같은 스케줄)으로 들어가 있는 걸 확인했습니다. 이대로 두면
내일 아침 9시에 자동 실행이 두 번 겹쳐서 돌아가고, 슬랙에도 같은 알림이
두 벌씩 올라갑니다. GitHub 저장소에서 둘 중 하나(`main.yml` 쪽을 추천합니다 —
이름이 헷갈리니까요)를 지워주세요.

## 지금 감시하는 곳

- 서울특별시교육청 공지사항 (`www.sen.go.kr`)
- 서울특별시교육청 보도자료 (`enews.sen.go.kr`)
- 뉴스와이어 MY뉴스 RSS — `NEWSWIRE_RSS_URL`을 설정했을 때만 켜집니다
- 대한민국 정책브리핑 korea.kr 보도자료 — 중앙부처 전체 통합 목록 (교육부 포함)

서울시청 공식 보도자료(`www.seoul.go.kr`)와 교육부 보도자료(`www.moe.go.kr`)도
넣어달라고 하셔서 시도했는데, 둘 다 목록이 자바스크립트 위젯으로 렌더링되는
방식이라 지금 이 코드처럼 단순 HTTP 요청으로는 목록을 못 읽어옵니다. 서울시청
쪽은 `seoulboard.seoul.go.kr`이라는 별도 위젯 서버가 데이터를 채워주고, 교육부
쪽도 비슷한 구조입니다. 대신 korea.kr 정책브리핑에 교육부를 포함한 모든
중앙부처 보도자료가 올라오니, 교육부만 보고 싶으면 `KOREA_KR_MINISTRY_FILTER`
변수를 `교육부`로 설정하세요(다만 이건 지자체가 아니라 중앙부처 통합 창구라
서울시청 자체 보도자료는 다루지 않습니다). 서울시청 쪽은 브라우저 자동화가
필요해서 다음 단계로 남겨뒀습니다.

다른 소스를 더 추가하고 싶으면 `djinn_lite/sources.py`에 같은 형태의 함수를
하나 더 만들고 `fetch_all()`에 연결하면 됩니다.

## 매시간 벌어지는 일

1. 하루 가까이 지난 알림들의 👍(기사감)/👎(아니다) 반응 개수를 세어
   `state/feedback_log.csv`에 기록합니다. (나중에 분류 기준을 다듬을 근거 데이터)
2. 감시 중인 소스에서 최근 글을 가져와, 이미 처리한 글(`state/seen.json`)은 걸러냅니다.
3. 같은 내용을 여러 기관이 낸 문서를 한 건으로 묶습니다 (`dedupe.py`).
4. 새 글들을 한꺼번에 LLM에 보내 두 관점(당사자성·또래 관심사)의 등급, 판단 이유,
   문서를 특정하는 개체명을 받습니다.
5. **우선순위가 높은 순으로 정렬해** 슬랙 `#진-알림` 채널에 올리고, 👍/👎 반응을
   미리 달아둡니다. 맨 앞에 그날 몇 건을 어떤 등급으로 걸렀는지 알리는 머리말이
   붙고, 같은 등급 안에서는 최신 글이 먼저 옵니다. 지금 단계는 우선순위와 상관없이
   전부 올립니다. 분류 기준이 충분히 검증되면
   `config.MIN_PRIORITY_TO_POST`를 "중"으로 올려 절차성 공고를 자동으로
   숨기는 것을 검토하세요.
6. 알림 기록 웹 페이지(`docs/index.html`)를 다시 만듭니다 (`site.py`).
7. 바뀐 상태 파일과 페이지를 저장소에 다시 커밋합니다 (GitHub Actions가 매번 새 컨테이너로
   뜨기 때문에, 이렇게 저장소 자체를 "기억 장치"로 씁니다).

## 시작하는 방법

### 0. 이 폴더를 GitHub 저장소로 올리기

기존 토끼풀 저장소가 있다면 이 폴더 전체를 그 안의 하위 폴더로 넣어도 되고,
새 저장소를 만들어도 됩니다. 새로 만든다면:

```bash
cd tokipul-djinn-lite
git init
git add .
git commit -m "init: 진(DJINN)-lite"
git branch -M main
git remote add origin <새로 만든 저장소 URL>
git push -u origin main
```

### 1. 슬랙 앱 만들기 (알림을 보내려면 반드시 필요)

이 세션에서 미리 `#진-알림` 채널(`C0BRLQBLGR3`)을 만들어두고 안내 메시지를
올려뒀습니다. 하지만 자동으로 돌아가려면 **이 코드 전용의 정식 슬랙 봇 토큰**이
따로 있어야 합니다 (지금 이 대화가 쓰는 연결과는 별개입니다).

1. https://api.slack.com/apps 에서 "Create New App" → "From scratch" 선택
2. 이름(예: 진-DJINN 봇)과 토끼풀 워크스페이스 선택
3. 왼쪽 메뉴 "OAuth & Permissions" → "Scopes" → "Bot Token Scopes"에 아래 권한 추가
   - `chat:write` (메시지 전송)
   - `reactions:write` (👍👎 미리 달기)
   - `reactions:read` (반응 집계)
   - `channels:read` (공개 채널 정보 조회, 선택)
4. 같은 페이지 위쪽 "Install to Workspace" 클릭 → 권한 승인
5. 발급된 "Bot User OAuth Token" (`xoxb-`로 시작) 복사
6. 슬랙에서 `#진-알림` 채널에 들어가 `/invite @봇이름`으로 봇을 초대

### 2. Anthropic API 키 준비

https://console.anthropic.com 에서 API 키를 발급받으세요. 하루 한 번, 새 글
몇 건을 짧게 분류하는 정도라 비용은 매우 적게 듭니다 (한 달에 몇백 원~천 원대

**모델 이름은 꼭 직접 확인하세요.** 이 코드는 모델 ID를 하드코딩하지 않고

현재 제공되는 모델 중 가장 가볍고 저렴한 것을 골라 아래 3단계의

저장소의 "Actions" 탭에서 "진(DJINN)-lite 일일 실행" 워크플로를 찾아

슬랙에 아무것도 올리지 않고 기록 페이지만 다시 만듭니다.

## 분류 기준 (상/중/하)

`djinn_lite/classify.py`의 `SYSTEM_PROMPT`에 그대로 들어가는 기준입니다. 편집회의에서
코드를 열지 않고 검토할 수 있도록 여기에도 옮겨둡니다. 근거가 된 판정 이력 전체는
별도 기준 문서에 있습니다.

### 두 관점으로 따로 보고, 높은 쪽을 택한다

원본 진은 중앙 모델과 지역 모델의 확신도를 합칠 때
`R = R_l·R_c + R_l²(1−R_c) + R_c²(1−R_l)` 를 씁니다. 둘 중 하나만 높아도 최종 점수가
높아지는 식인데, 논문의 표현대로 **거짓 음성이 거짓 양성보다 나쁘기** 때문입니다.
중요한 문서를 아예 놓치는 쪽이 더 큰 손실이라는 판단입니다.

여기서도 같은 원칙을 씁니다. 모델을 두 개 훈련하는 대신 프롬프트 안에서 두 관점으로
따로 채점하고, **높은 쪽을 최종 등급으로** 삼습니다.

| 관점 | 묻는 것 | 해당하는 것 |
|---|---|---|
| **당사자성** | 청소년의 권리·의무·일상에 규칙이 바뀌는 수준으로 닿는가 | 교칙·생활규정 제개정, 급식·통학·학교시설 제도 변경, 입시 제도, 청소년을 포함하거나 배제하는 복지·교통 정책, 학교 안전·인권, 예산·시설 배정 공정성, 언론과 표현의 자유 |
| **또래 관심사** | 규칙으로 닿지 않아도 또래가 알아야 할 소식인가 | 정치 현안, 재난·안전, 기후·환경, 과학·우주 성과, 국제 사안, 사회의 모습을 보여주는 전국 통계, 또래의 성취 |

두 번째 관점을 빠뜨리면 민방위 훈련, 후쿠시마 오염수 대응 브리핑, 달 탐사 성과 같은
것을 전부 놓칩니다. 실제로 5회차에서 갈린 14건 중 12건이 이 유형이었습니다.

| 등급 | 조건 |
|---|---|
| 🔴 상 | 두 관점 중 하나가 뚜렷하고, 누구를 만나 무엇을 확인하면 기사가 되는지 각도가 보인다 |
| 🟡 중 | 관련은 있으나 간접적이거나 대상이 좁다. 배경 취재가 더 필요하다 |
| ⚪ 하 | 어느 관점으로도 또래와 이어지지 않는다 |

### 판정하며 배운 것 — 반드시 지킬 네 가지

1. **발표 기관으로 버리지 않는다.** 268건 중 교육부는 17건 중 12건이 기사감이었고
   고용노동부는 11건 모두 아니었습니다. 그래서 5회차에 "기관으로 걸러도 되는가"를
   시험했는데 깨졌습니다. 기사감이 0%였던 식약처에서 학교 급식시설 점검이,
   산림청에서 청소년 국제산림협력이 나왔고 둘 다 기사감이었습니다. 그 기관들이
   0%였던 것은 청소년 관련 문서를 안 냈기 때문이지 기관이 무관해서가 아닙니다.
   기관은 **먼저 훑을 순서**를 정하는 데만 씁니다 (`config.HIGH_YIELD_SOURCES`).
   다만 채널 구분은 유효해서, 서울시교육청은 보도자료가 10건 중 7건인 반면
   공지사항은 4건 중 0건이었습니다.
2. **문서 종류로 버리지 않는다.** 조달·규정 개정처럼 절차성으로 보여도 내용에
   ①학생이 접촉하는 시설·물품의 안전 ②심의·감시 기구의 폐지·축소 ③예산·조달의
   공정성이 걸리면 등급을 낮추지 않습니다. 인조잔디 자재 선정 공고와 운영위원회
   폐지에 따른 규정 개정이 그렇게 걸러졌습니다.
3. **제목만 보지 않는다.** '2029학년도 대학수학능력시험 시행일'에는 학생이라는 말이
   없지만 지금 중학생이 치를 시험입니다. 제목 키워드로 거르다 놓쳤습니다.
4. **억지로 잇지 않는다.** "청소년과 이어질 수 있다"는 식의 두 단계 건너뛴 연결은
   예외 없이 틀렸습니다. 자살예방·노동·주거는 토끼풀의 주제이지만 대상이 성인이면
   내립니다.

`state/feedback_log.csv`가 쌓이면 등급별 👍/👎 비율을 비교해 이 기준을 계속
갱신하세요. 특정 유형의 "하"가 계속 👍를 받는다면 그 유형만 승격하는 식입니다.

|---|---|
| 중앙 모델 + 지역 모델, 하나만 높아도 높게 집계 | 두 관점 채점 후 높은 쪽 채택 (`classify._higher`) |
| 좋아요/싫어요로 교정 피드백을 모아 재학습 | 슬랙 👍/👎를 `feedback_log.csv`에 축적 |
| 개체명 추출 후 TF-IDF로 재정렬해 표시 | 문서를 특정하는 개체명만 뽑고 흔한 기관명은 제외 (`config.ENTITY_STOPWORDS`) |
| 카드에 관련도 점수를 노출해 설명 가능성 확보 | 알림에 두 관점 등급과 판단 이유를 함께 표시 |
| 요약은 독자에게 보이지 않고 기자의 판단 보조로만 | AI는 기사 문장을 쓰지 않음. 프롬프트에 명시 |
| 지자체마다 다른 수집 방식을 설정 템플릿으로 흡수 | 소스별 함수 분리 (`sources.py`) |
| 정보공개청구 자동화는 의도적으로 배제 | 정보공개청구 자동화 없음. 아래 참고 |

**정보공개청구는 자동화하지 않습니다.** 논문은 요청이 감당 못 할 규모로 쏟아질
위험이 있고, 노르웨이 법이 청구 범위를 "합리적" 수준으로 요구하며, 모든 비공개
문서에 대한 자동 청구는 자원 부족을 이유로 거부될 것이라 이 기능을 뺐다고
밝혔습니다. 한국 정보공개포털도 사정이 같고, 학생 언론이 대량 자동 청구를 넣으면
거부는 물론 앞으로의 취재 관계까지 나빠집니다. 표적을 정한 수동 청구만 하세요.

## 웹 기록 페이지

슬랙은 흐르는 매체라 사흘 전 알림을 다시 찾기 어렵습니다. 그래서 지금까지 올라온
알림을 한자리에 모은 정적 페이지를 **매시간** 다시 만듭니다.

화면 구성은 이트롬쇠가 실제로 쓰는 진 화면을 따랐습니다. 카드 하나가 가로로 세 칸이고,
왼쪽에 평점, 가운데에 제목·판단 이유·개체명 알약 태그, 오른쪽에 상세 정보와 판정
버튼이 들어갑니다. 위에는 통계 숫자를 늘어놓지 않고 곧바로 기간·출처·검색·정렬
도구와 결과 건수만 둡니다. 원본이 그렇게 되어 있습니다.

**평점**은 `config.rating()`이 논문의 집계 함수로 계산합니다. 두 관점 등급을 확신도로
바꿔 `R = R_l·R_c + R_l²(1−R_c) + R_c²(1−R_l)` 에 넣은 값에 10을 곱한 것이라,
둘 중 하나만 높아도 점수가 높게 나옵니다. 상·상은 9.72, 상·하는 8.26, 하·하는 0.61이
됩니다.

아직 판정하지 않은 카드에는 **슬랙 메시지로 바로 가는 링크**가 붙습니다. 정적 페이지라
여기서 직접 판정할 수는 없고, 판정은 슬랙에서 하면 다음 실행 때 결과가 페이지에
반영됩니다.

`state/feedback_index.json`과 `state/feedback_log.csv`를 읽어 `docs/index.html`
하나를 만드는 방식이라 서버가 필요 없습니다. 데이터베이스도 없고, 저장소가 그대로
기억 장치 겸 배포 대상이 됩니다.

### GitHub Pages 켜기

1. 저장소 → Settings → Pages
2. Source를 **Deploy from a branch** 로 두고, Branch를 `main`, 폴더를 **`/docs`** 로 지정
3. Save를 누르면 몇 분 뒤 `https://<계정>.github.io/<저장소>/` 로 열립니다

주소는 공개되므로, 링크를 아는 사람은 누구나 볼 수 있습니다. 지금 페이지에는
공공기관이 이미 공개한 자료의 제목·링크와 AI 판단 이유만 들어가고 취재 내용은
들어가지 않지만, 비공개로 두고 싶으면 Pages를 켜지 말고 저장소 안에서
`docs/index.html`을 내려받아 여세요.

직접 만들어보려면:

```bash
python -m djinn_lite.site              # docs/index.html 생성
python -m djinn_lite.site --fragment   # 바깥 문서 태그 없이 본문만 출력
```

## 슬랙 알림 형식

슬랙은 일반 마크다운이 아니라 자체 방언(mrkdwn)을 씁니다. 굵게는 별표 **하나**
(`*굵게*`)이고 별표 둘은 굵게가 되지 않습니다. 링크는 `<주소|보일 글자>` 꼴이며,
`<`와 `&`가 제목에 들어가면 슬랙이 태그로 읽어버리므로 코드에서 미리 바꿉니다
(`slack_client._mrkdwn_escape`).

본문은 한 덩어리 문자열이 아니라 Block Kit으로 조립합니다. 출처·등급·개체명 같은
부가 정보를 context 블록에 담으면 작고 흐리게 렌더링되어, 제목과 판단 이유가 먼저
눈에 들어옵니다. 하루에 수십 건이 쌓이는 채널에서는 이 차이가 큽니다.

```
🔴 서울시교육청, 휴대전화 등 스마트기기 사용 제한 관련 토론회 개최    ← section, 제목 링크
`상`  서울시교육청 보도자료  ·  2026-08-20                        ← context, 작게
> 휴대전화 사용 제한은 학생생활규정과 직결됩니다.                    ← section, 인용
당사자성 `상` · 또래 관심사 `중`  |  🏷 정근식 · 서울학생참여위원회   ← context, 작게
기사감이면 👍, 아니면 👎                                          ← context
───────────────                                              ← divider
```

## 알아두면 좋은 한계

- **페이지네이션 미지원**: 서울시교육청 두 게시판은 첫 페이지(최신 글 약 10건)만
  읽습니다. 하루 1~3건 정도 올라오는 속도라 매일 실행하면 충분하지만, 글이
  갑자기 몰리면 일부를 놓칠 수 있습니다. korea.kr과 뉴스와이어는 최신 글이
  많아 상대적으로 여유가 있습니다.
- **사이트 구조 변경에 취약**: HTML을 직접 파싱하는 소스(서울시교육청,
  korea.kr)는 사이트가 게시판 디자인을 바꾸면 `djinn_lite/sources.py`의
  파싱 로직도 손봐야 합니다. 뉴스와이어는 표준 RSS라 상대적으로 안정적입니다.
- **서울시청·교육부는 아직 못 붙임**: 위 "지금 감시하는 곳"에 적은 대로,
  자바스크립트 위젯 기반이라 단순 요청으로는 안 됩니다.
- **분류는 완벽하지 않음**: LLM 판단은 참고용입니다. 실제 기사화 여부는 반드시
  학생 기자가 원문을 직접 확인하고 결정해야 합니다. 원본 진 시스템의 윤리 원칙과
  동일합니다.
- **판단 이유에 사실과 다른 내용이 섞일 수 있음**: 논문은 자기들이 쓴 모델의 환각률을
  5.1%로 명시하고, 월 12,000건 처리 시 약 612건의 요약에 오류가 섞인다고 숫자로
  밝혔습니다. 이 코드도 하루 50~60건을 처리하니 월 1,800건 규모이고, 알림에 붙는
  💡 판단 이유 중 일부는 틀릴 수 있습니다. **이유만 읽고 판단하지 말고 반드시 원문
  링크를 여세요.** 등급과 개체명이 이유를 보완하도록 함께 표시하는 것도 같은 이유입니다.
- **본문이 첨부파일에만 있는 문서**: 정책브리핑 문서 상당수가 본문 없이 HWP·PDF
  첨부파일만 올립니다. 그런 문서는 제목과 발표 기관만으로 판단하게 되어 정확도가
  떨어집니다. 공공기관이 기계가 읽을 수 없는 형태로 자료를 올린다는 사실 자체가
  취재거리이기도 합니다.
